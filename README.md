# JATLAS

**Jav Actress Tier Ledger & Asset System**

JATLAS 是为 NAS + Emby 本地 AV 收藏设计的资产台账。

NAS 保存文件，Emby 负责识别和播放。JATLAS 管理的是两者之外的问题：收藏里有哪些演员，各自有多少影片，哪些内容已经超过预期，以及有限的容量应该留给什么。

它不帮你获取更多内容，也不替代现有媒体库。它把已经存在的收藏整理成一套能查看、能比较、能持续维护的记录。

## 收藏需要的不只是存储

收藏规模小时，文件夹和记忆通常够用。数量增加以后，情况会逐渐失去边界：同一位演员的影片不断累积，Emby 中的条目和真实文件未必一致，新增目录没有进入台账，硬盘快满时才开始临时清理。

问题不只是容量有限，而是缺少取舍依据。你可能知道自己偏爱哪些演员，却很难随时回答：她目前有多少部影片，是否已经超过原先设定的范围，哪个分类正在持续膨胀，最近的数量变化来自哪里。

JATLAS 把这些模糊判断变成可见的数量、规则和记录。清理不再从“硬盘又满了”开始，而是从已经暴露出来的超限项开始。

## JATLAS 能做什么

### 用分类表达收藏优先级

每位演员归入一个明确分类。不同分类可以设置不同的单人影片上限和分类总量上限：核心收藏可以使用更高的数量上限，普通收藏接受更严格的限制，仍在观察的内容不再默认无限增长。

分类不是评价演员的标准，而是分配个人存储资源的规则。它让“喜欢程度”真正影响保留数量。

### 把 NAS 中的已有文件纳入台账

为分类设置存储目录后，JATLAS 可以扫描其中的一级文件夹，识别演员名称，并批量导入尚未建档的演员。

这套流程适合已经积累了一批本地文件、后来才开始整理的人。无需从空白台账重新录入，现有目录本身就是整理的起点。

### 与 Emby 核对人物和影片数量

JATLAS 可以补全演员对应的 Emby ID，并刷新 Emby 统计到的影片数量。Emby 继续负责媒体识别和播放，JATLAS 则用同步到的数量计算分类压力和单人风险。

单个演员可以独立刷新，一个分类也可以批量处理。影片数量减少时，台账会同步实际数量；只有数量增加时，才推进“资产扩增时间”。

### 让超量和长期未增长的收藏显形

资产页集中显示演员总数、现役与引退人数、影片总量、单人超限影片、单人超限演员以及长期未扩增项。

进入分类后，可以继续查看：

- 分类影片总量占上限的比例
- 哪些演员已超过单人上限
- 哪些演员处于预警或超限状态
- 哪些资产已经较长时间没有增加
- 最近六个月的入库、出库和净变化

这些状态不会替用户决定删除什么。它们只是把最需要检查的地方排到眼前。

### 保存演员资料，并自动判断现役或引退

演员档案可以记录头像、别名、出生日期、身材信息、出演时间和标签，也可以从 Minnano 获取可填充的资料，确认后再保存。

现役或引退不需要单独维护：填写出演结束时间即视为引退，未填写则视为现役。引退演员的年龄和从业年限停留在出演结束时，不会继续随当前年份增长。

### 让每次操作都有下文

扫描目录、导入演员、补全 Emby ID、刷新影片数量以及资料变更，都会进入右侧操作日志。日志会保留处理对象、数量变化、跳过原因和失败信息。

批量任务可以取消，失败项可以重试。左侧只保留操作入口，执行过程和结果统一在日志中查看。

## 一次典型的整理过程

1. 按自己的收藏优先级建立分类，并设置单人上限和分类总量上限。
2. 为分类指定 NAS 存储目录，扫描已有演员文件夹并导入台账。
3. 补全 Emby ID，刷新每位演员的影片数量。
4. 从资产总览进入压力较高的分类，检查预警、超限和长期未扩增的演员。
5. 调整分类、整理文件或修正资料，再通过操作日志确认结果。

JATLAS 不要求一次整理完所有历史收藏。先把真实数量纳入台账，再逐步建立适合自己的保留规则即可。

## 适合谁

JATLAS 面向已经使用 NAS 和 Emby 管理本地 AV 收藏，并且开始在意容量、分类和长期维护的人。

如果收藏仍然很小，或者只需要搜索和播放，文件夹与 Emby 本身已经足够。只有当“留下什么、留下多少、哪里需要整理”成为持续问题时，这套台账才有价值。

## 产品边界

JATLAS 是本地优先的私人资产工作台。台账数据保留在本机，核心使用流程不需要账号：

- 不提供内容下载
- 不提供公开分发
- 不提供账号体系
- 不替代 NAS
- 不替代 Emby 或其他媒体播放器
- 不自动替用户删除文件或决定收藏价值

它只负责把本地收藏的数量、规则、变化和风险放在同一个地方，让每次取舍都有依据。
