# JATLAS 发布检查清单

发布前按下列顺序检查。不要带着未说明的失败项打包。

## 代码与测试

- 运行 `npm run verify`，确认代码检查、全量测试、Electron 主进程编译、Renderer 类型检查和构建全部通过。
- 检查 `git diff --check`，不留尾随空格或冲突标记。
- 检查 `git status --short`，不提交数据库、日志、密钥、`dict/`、`release/` 和构建产物。

## 数据与迁移

- 用当前版本数据库启动一次，确认数据可读写。
- 用一份可丢弃的旧版本数据库走完“检测旧版本 → 备份 → 升级”。
- 验证取消切换会恢复原数据库；切换失败后，原数据库仍可正常打开。
- 确认配置文件权限只开放给当前用户。

## 核心流程

- 新建、编辑、删除演员，确认资产日志与数据变化同时成功或同时回滚。
- 扫描分类存储目录，导入新演员，并确认重复名称不会重复创建。
- 同步 Emby ID 和影片数量。Emby 请求失败时应显示失败，不得把原数量写成 0。
- 启动、取消和重试批量任务，确认操作日志的进度、完成、取消和失败状态正确。

## 界面

- 在深色和浅色模式下查看资产总览、分类详情、演员编辑、系统设置和操作日志。
- 在最小窗口 960 × 640 下确认没有不可达的按钮，长表格可滚动查看。
- 只用键盘走一遍顶部导航、表单、分类表格和日志分隔条，确认焦点可见。

## 打包

- 运行对应平台的 `npm run desktop:pack:mac` 或 `npm run desktop:pack:win`。
- 在不含开发依赖的环境中启动产物，确认 Prisma 引擎、SQLite 数据库和图标资源正常。
- 记录版本号、目标平台、验证人和已知限制。
